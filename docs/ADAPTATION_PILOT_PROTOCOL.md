# Adaptation 004 — pilot protocol 1

Status: design written before the outcome runs. This is a small development pilot, not a confirmatory study or a claim of algorithmic novelty. The initial Git commit of this document establishes the public design record. Study 003 continues separately and is not modified.

## Question and predictions

Can choosing a pair by its performance **after brief learning** improve adaptation to withheld problems enough to repay the computation used to choose it?

The proposed selector minimizes the loss of a pair's averaged probabilities after temporary copies learn several development problems. It rewards useful joint performance, not disagreement for its own sake. The essential ablation chooses two individually fast learners using exactly the same temporary copies. If the proposed selector cannot beat that ablation, this pilot does not establish a benefit from complementary learning responses.

Directional prediction: response-pair will have lower prospective adaptation loss than current-pair and response-individual. Competing prediction: probing costs more than it earns, and ordinary continued training wins. No result will be described as evidence for improved LLM intelligence, autonomous self-replication, or indefinite improvement.

## Fixed design

- Eight paired world seeds: 24001–24008. All five methods start from identical sets of four independently initialized networks in each world. No outcome-based seed exclusion.
- Sixteen rounds, with the current task changing every four rounds. The family order is linear, XOR, radial, linear. Each task has new random geometric parameters.
- Network: 2 inputs → 32 tanh hidden units → 1 sigmoid output, 129 parameters. Binary cross-entropy, online SGD, learning rate 0.04; no optimizer memory, dropout, or evolved learning rates. Xavier-uniform weights, zero biases.
- Each initial model trains on 128 examples of the first current task. All methods incur the same warm-up cost.
- Every round, all models receive identical prefixes of the same task-specific training stream. Different lengths reflect the method's compute allocation. Selection uses 56 fresh examples shared across methods.
- At a replacement, two selected survivors remain unchanged. Each produces one child by copying all weights and independently perturbing each parameter with probability 0.05 by a uniform value in [-0.05, 0.05]. Child mutation draws are paired by round and child index across selection methods. No hidden retries or offspring rejection. Children begin training next round.
- Snapshot and future evaluation occur **before** that round's births. Births occur after rounds 1–15; round 16 only selects the final pair.

## Five methods

| ID | Which pair is used? | Replacement | Current training examples/model/round |
|---|---|---|---:|
| response-pair | Lowest mean development loss of averaged probabilities after learning | Keep two; copy/perturb two | 784 |
| response-individual | Lowest mean individual development loss after learning, summed over the pair | Same | 784 |
| current-pair | Lowest current loss of averaged probabilities | Same | 1,024 |
| current-individual | Lowest summed current individual loss | Same | 1,024 |
| continual | Lowest current loss of averaged probabilities for the readout | Keep all four; no births | 1,024 |

For both response selectors, eligible pairs must have current ensemble loss no more than 0.03 nats above the best current pair. This present-competence guard is fixed. All six pairs are considered, and lexicographic slot order breaks exact ties. There is no separate reward for large weight distances or errors.

Each response selector makes three independent temporary copies of each of its four models. Each copy learns 56 examples from a development task (one linear, one XOR, one radial), then predicts a separate 56-example development validation set. Every round uses new development task parameters. Temporary weights are discarded; only the selected parent indices influence the actual population. The individual ablation has exactly the same probe cost and eligibility guard as the proposed method.

## Tasks and withheld evaluation

Inputs are continuous uniform points in [-1,1]^2. Targets are generated by explicit hidden rules; learners receive points and labels, never rule parameters or a task identifier. This is adaptation to changing classification rules, not a growing library of simultaneously retrievable skills.

- Linear: a randomly rotated line with offset in [-0.3,0.3].
- XOR: agreement/disagreement of signs along rotated axes, with a random center in [-0.25,0.25]^2.
- Radial: an ellipse around a random center in [-0.25,0.25]^2, rotation in [0,2π), radius in [0.65,1], and axis multiplier in [1,1.6].
- Withheld-family diagnostic: a sinusoidal boundary, sin(3u + phase) + 0.5v > 0, using rotated coordinates. It never appears in current training or development probes.

At rounds 4, 8, 12 and 16, freeze the selected pair. Without changing that pair or the population, evaluate independent copies on six withheld tasks (two per familiar family) and two sinusoidal tasks. Each member learns the same 256-example stream. Measure averaged-probability loss and accuracy on 128 separate examples after 0, 16, 64 and 256 examples/member. Held-out task parameters and streams use a separate seed namespace. The same withheld tasks are reused across checkpoints for paired measurement, but are never supplied to selection, training, parameter tuning or stopping rules.

**Primary endpoint:** mean held-out binary cross-entropy at 16, 64 and 256 examples/member, averaged over the six familiar-family tasks and four checkpoints, then over the eight worlds. It is an equally weighted checkpoint average, not a continuous-time area integral. Lower is better. Each world, not each task or checkpoint, is the independent reporting unit.

Secondary descriptive endpoints: corresponding accuracy; zero-shot performance; sinusoidal-family performance; current-task performance; mean individual vs ensemble performance; both-member contribution (does the pair outperform each member after the same learning?); parent identities and generation depth. Current individual ablation and continual population are additional comparisons. No significance fishing among secondary endpoints.

The evaluator reads snapshots after the population run completes. Its outcomes cannot change any model, selection, stopping time or saved snapshot. An evaluation-disabled run must produce identical population snapshots.

## Compute accounting

A forward pass costs 96 dense neural multiply-accumulates (MACs): 2×32 + 32×1. A learning example costs 224 MACs: two forward-matrix-sized operations plus 32 output-to-hidden backpropagation MACs. Scalar activations, biases, sampling, pair averaging, loss calculations, copying and mutations are excluded from this conventional dense-MAC measure. We report wall time and counters rather than calling this exact hardware FLOP equality.

Per method per round:

- Current selection: 4×56 = 224 forward examples, 21,504 MACs.
- Ordinary methods: 4×1,024 = 4,096 learning examples, 917,504 MACs.
- Response methods: 4×784 = 3,136 current learning examples, 702,464 MACs; 4×3×56 = 672 probe learning examples, 150,528 MACs; 672 probe forward examples, 64,512 MACs.
- **Total: 939,008 dense neural MACs for every method every round.** Probe methods spend 24% fewer current-task training examples; probing is not free.
- Warm-up: 512 learning examples, 114,688 MACs per method.
- Future evaluation is a separate, identical measurement budget for every method: eight tasks, two models, 256 learning examples, four 128-example prediction checkpoints, at each of four population checkpoints. The measured copies are discarded. Current reporting reuses selection predictions.
- Total algorithm MACs per method/world: 15,138,816. Total future measurement MACs: 6,815,744. Combined total: 21,954,560.

The runner must assert exact equality of these counters; print measured runtime and peak RSS. Pair scoring and model mutation overhead differ and are explicitly outside the neural-MAC comparison.

## Analysis and decision rule

Publish every world and every method, plus configuration, source SHA-256, seed namespaces, selection records, compute ledgers and per-task outcomes. Report paired differences (response-pair minus comparator) with individual world values and descriptive 95% Student-t intervals, df=7. These intervals are not multiplicity-adjusted confirmatory tests.

Advance to a separately frozen confirmation study only if response-pair improves the primary mean by at least 0.005 nats over **both** current-pair and response-individual, wins each comparison in at least six of eight worlds, and does not trail continual by more than 0.005 nats. These are practical pilot screening thresholds, not statistical proof. Otherwise publish the negative/mixed result and do not launch a long-running version of this selector.

No changes to architecture, task distribution, learning rate, thresholds, seeds or stopping rule after seeing pilot outcomes. An implementation bug may require correction and a transparent rerun; preserve the invalid run and explain it. Engineering checks use separate seeds and do not inspect method rankings. Any later redesign gets a new protocol/version, rather than quietly replacing this pilot.

## Context

This builds on established ideas in ensemble selection, meta-learning and evolvability; novelty has not been established. Relevant primary work includes [ensemble selection](https://doi.org/10.1145/1015330.1015432), [MAML](https://proceedings.mlr.press/v70/finn17a.html), and [Evolvability ES](https://arxiv.org/abs/1907.06077). Anthropic's [replication article](https://www.anthropic.com/research/self-replicating-ai) motivates distinguishing learned weights from inherited external notes/workspace; this pilot studies the former. A later LLM memory-transfer experiment is contingent on useful evidence and has no scheduled run or API dependency here.
